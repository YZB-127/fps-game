# 3D 第一人称射击 · 联机方式说明

## 一句话
**联机不是双击 HTML 就能玩的**——这个页面本身没有服务器，必须先在**同一目录**跑 `node server.js`，然后**所有人用浏览器打开 `http://<这台机器的IP>:8000`**，进大厅选「联机混战」，一人建房拿 4 位房间号，其他人加入（每间最多 4 人）。

## 怎么启动服务器（两种方式，选一个）

### 方式一：双击「启动服务器.bat」（推荐）
双击 → 提示端口时直接按回车（用默认 8000）→ 窗口里打印出可用地址 → 浏览器打开 `http://127.0.0.1:8000`。
**这个黑窗口不能关**，关了服务器就停了。

### 方式二：手动敲命令
1. 按 `Win + R`，输入 `powershell`，回车；
2. 复制这两行（第二行的 `cd` 是进目录，路径照抄）：
```powershell
cd C:\Users\17821\Desktop\DSH\fps-game
node server.js
```
3. 看到 `联机大厅服务器已启动` 就成了，窗口别关；浏览器打开 `http://127.0.0.1:8000`。

换端口：`node server.js 9000`（本机已占用 8000 时用）。

### 启动成功长这样
```
  3D 第一人称射击 · 联机大厅服务器已启动
  ------------------------------------------------
  本机（房主自己）：http://127.0.0.1:8000
  局域网（把下面地址发给朋友，同一个 WiFi 就能直接进）：
      http://10.99.85.164:8000   [WLAN]
  ...
```
其中 **WLAN 那行的地址**就是发给朋友的地址（别用 VMware 的 `192.168.x.1`）。

### 停止 / 重开
- 停止：在那个黑窗口按 `Ctrl + C`（或直接关窗口）；
- 报 `端口 8000 已被占用`：说明已经有一个在跑了 —— 要么直接用，要么换个端口 `node server.js 8001`。

## 为什么不能双击打开
- 双击打开时地址是 `file://`，页面里的 `location.host` 是空的，WebSocket 只能回落到 `ws://127.0.0.1:8000` —— 那是**你自己这台机器**，对方电脑连不上。
- 走 `http://` 打开时页面会自动用 `ws://当前地址` 当联机地址，双方自动连到跑服务器那台机器，什么都不用填。
- 另外页面用 ES Module + importmap 加载 Three.js，`file://` 下还可能被浏览器的安全策略拦掉。

## 三种联机场景

### 1. 本机双开自测（最快验证）
在 `fps-game` 目录执行：
```
node server.js
```
两个浏览器窗口都打开 <http://127.0.0.1:8000> → 都点「联机混战」→ 窗口A「＋ 创建房间」记下 4 位房间号 → 窗口B 点列表里的【加入】（或输入房间号）→ 窗口A 点【开始游戏】。想测 3~4 人就把窗口再开几个，都加入同一个房间号。

### 2. 同一个 WiFi / 局域网联机（推荐）
1. 只在**一台**机器上跑 `node server.js`（房主机器，服务器启动时会直接把可用的局域网地址打印出来）；
2. 双方打开 `http://<房主机器IP>:8000`（本机测试时打印的是 `http://10.99.85.164:8000`，以实际打印为准）；
3. 如果对方连不上：Windows 防火墙会拦入站 8000 端口，用**管理员** PowerShell 放行一次：
```
netsh advfirewall firewall add rule name="FPS 8000" dir=in action=allow protocol=TCP localport=8000
```
4. 注意别用 VMware 虚拟网卡那几个 `192.168.x.1`：那是虚拟机内网地址，手机/别的电脑连不上，用 WLAN 那个 `10.x` 的地址。

### 3. 不在同一个网络（异地）—— 三种办法
| 办法 | 怎么做 | 适合 |
|---|---|---|
| 内网穿透（最简单） | 房主机器跑 `node server.js`，另开一个窗口跑 `cloudflared tunnel --url http://127.0.0.1:8000`（或 `ngrok http 8000`），把生成的 `https://xxx.xxx` 地址发给朋友 | 零配置，双方都不用装东西 |
| 虚拟局域网 | 双方装 Tailscale/ZeroTier，加入同一网络后用房主的虚拟网卡 IP 访问 `http://100.x.x.x:8000` | 延迟最低，长期联机 |
| 端口映射 | 路由后台把 8000 端口映射到房主机器内网 IP，朋友访问公网 IP | 需要路由器权限，安全性自己评估 |

注意：穿透/虚拟网卡给的地址若是 `https://`，页面会**自动**用 `wss://` 连接，不需要手动改。只有一种情况要手填大厅里的「服务器」输入框：页面和服务器地址不一致时（比如页面是 `https://xxx`，服务器在另一台机器的 `ws://192.168.1.5:8000`）。

## 玩法：联机混战（2~4 人）
选「联机混战」进大厅联机。**场上没有机器人**，只有你们几个人：

- **复活死斗**：每人 100 血，被击倒后 2.5 秒在随机点复活，击杀累计，**先到 15 杀获胜**
- **每局重抽出生点**：从 38 个候选位置里取 N 个，贪心挑「最小两两间距」最大的一组，保证都不卡在箱子/内墙里，且朝向其余出生点的中心
- **复活点**会挑「离其他活人最远」的候选位置，不会刚复活就被人堵脸
- **每个人头顶挂着昵称名牌**，边框是各自的阵营色，按距离缩放所以远近都读得清；配合模型的眼睛和手里的枪，一眼就知道对面是谁、朝哪、拿的什么
- 左上角计分板实时显示每个人的击杀数，自己那行高亮，阵亡的人变暗；阵亡时屏幕中央显示复活倒计时
- 2 人、3 人、4 人都能开；房主至少要等到第 2 个人进来才能点开始（每间最多 4 人）
- 想再打一局，任意一方点【再来一局】都行——实际重开由**房主**统一发起，所有人同时复位、出生点也重抽
- 血量、击杀、复活、胜负全部**房主权威**：别人只上报位置和开火，命中由房主裁决

判定是打身体和打头的：爆头 ×1.5 伤害。子弹会被箱子和墙挡住，不能穿墙打人。

**房主中途退出房间就解散**——对局状态（谁多少血、谁几杀、谁在等复活）只在房主手里，没法交接。想换人当房主只能重新建房。

## 服务器做的事
`server.js` 零依赖，一个进程干两件事：
1. **静态服务**：把 `index.html` 通过 HTTP 发出去（所以必须走 `http://` 打开）；
2. **WebSocket 大厅中继**：昵称登录、房间列表、创建/加入/离开房间、房间内对局消息转发。规则是**房主权威**：
   - 登录时给每个连接分配一个房间内唯一的玩家 id，对局消息带上 `from`，房主才知道这条上报是谁的；
   - **房主发的**消息广播给房间里其他所有人（全量快照、伤害、复活、开局、结算）；
   - **其他人发的**消息只转给房主（位置上报、开火、请求重开），不会在普通玩家之间互相刷。

常用参数：`node server.js 9000` 或 `set PORT=9000 && node server.js`。关掉服务器（Ctrl+C）后所有人都联不上，这是正常的。

## 自测
```
node test-mp.js      # 联机流程：4 人容量 / 广播 / 只转房主 / 离开解散（约 3 秒）
node test-deep.js    # 深度：大消息、分片、畸形输入、30 并发、半关闭回收、心跳（约 70 秒）
```
`test-mp.js` 会自己拉起服务器、模拟浏览器客户端，把整套联机流程跑一遍，全绿说明服务器没问题。
